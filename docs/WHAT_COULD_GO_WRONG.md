# What could go wrong with Bird Strike Radar, and how I tested it

A tool that rates safety risk is itself a system that can fail. I treated it the way MIL-STD-882E treats
any system: identify how it could mislead someone, mitigate each hazard, verify the mitigation, and state
what's left. The worst outcome isn't a crash. It's a user believing a wrong number, so most hazards below
are about **being confidently misleading**.

| # | Hazard: how the tool could mislead | Mitigation | How it was tested | What's left |
|---|---|---|---|---|
| 1 | **Reporting growth read as rising hazard.** Voluntary reporting has grown a lot | Model only *damaging* strikes, which are reported far more completely; a national year effect and airport trends absorb reporting drift; the map shows *recent* (2023-25) conditions | All reports per 10k operations roughly doubled 2010-25, damaging strikes rose far less ([data report](../reports/week1_data_quality.md)). Fitted year effect: 0.90 → 1.23 | Hazard and reporting thoroughness can't be fully separated. A thorough-reporting airport still looks riskier. Stated on the site |
| 2 | **Unknown damage counted as "no damage",** making airports look safer | Blank damage = unknown, not none; excluded from the count (a documented, one-directional underestimate) | `test_blank_damage_is_unknown_not_none`. The FAA's own damage flag codes blanks as 0, and the test guards against using it | A slight underestimate, stated in the README and the planner |
| 3 | **A small airport with one unlucky strike tops the map** | Partial pooling: sparse airports borrow from their flyway and the nation. Airports not distinguishable from national are faded | Simulation with known truth: rank correlation 0.74 vs 0.52 for the simpler baseline. Forecast test: raw rates called **213** held-out airport-months impossible that then had strikes | The raw view is still available, labelled "own counts, no pooling" |
| 4 | **Overconfident intervals:** narrow ranges that miss the truth | Negative-binomial model (counts are clumpier than Poisson); hierarchical uncertainty; future years get their own uncertainty | Simulation: 92% of 90% intervals contain the truth. Held-out 2023-25: 96% of 90% ranges held where the model expected 2+ strikes (baseline 87%); outer-tail shares 4.5% / 5.7% vs 5% ideal ([evaluation](../reports/week5_evaluation.md)) | 2025 came in above the model's range, so forecasts lean low. Failure cases are listed, not hidden |
| 5 | **Bad data joins:** a traffic file for the wrong year, a duplicate month, a renamed airport | Pipeline stops on wrong-year files, subtotals that don't add up, or duplicate airport-months; airport ID crosswalk with fallback | These checks caught real mislabelled files during download. Unit tests for two-digit years, unknown airports and missing operators | Checks cover structure, not every value |
| 6 | **The site shows different numbers than the model** | One versioned JSON file is the only path from model to site | A JavaScript test recomputes the 882E level for all 3,192 airport-months and compares with Python. It **caught a real bug**: rounding to 4 decimals flipped a level at a threshold. Fixed by exporting 6 significant digits | Only the 10,000-operation levels are cross-checked |
| 7 | **An 882E label quoted without its exposure,** or the matrix tuned to make the map look nicer | Appendix A thresholds used unmodified (`test_risk_matrix_matches_standard`); exposure stated next to every level; the planner shows how the level changes with plan size | Sacramento in October: High per 10,000 operations, Serious for 60, Medium for one round trip. A unit test checks that a small plan drops the level as the standard says it should | Users can still screenshot a label out of context |
| 8 | **Silent display failure:** the map loads with no dots, which reads as "no risk" | Layers added on an explicit style-ready signal, with a retry | Reproduced the race in a headless browser (data arriving after the basemap): the old code showed no dots, the fixed code shows all 266 | Not yet an automated test in CI |
| 9 | **Used for real operational decisions** | "Not for operational use" on every panel; the planner lists its assumptions (no time of day, altitude, aircraft type; national severity shares; independence) | Review only | It's a teaching tool. Real planning needs local wildlife data and operator expertise |
| 10 | **Personal data exposed** (reporter names, tail and flight numbers) | Dropped at load; never reach processed data, git or the site | `test_pii_is_dropped` | None known |

**What I'd add next:** an end-to-end browser test in CI for hazard 8, running the website tests on every
deploy, time-of-day and altitude exposure from BTS data, and a check of the biggest forecast misses against
the strike narratives.
